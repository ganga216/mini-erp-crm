1. Project Overview

This web application is a lightweight ERP/CRM system designed for wholesale and distribution companies. It allows internal employees (Sales, Warehouse, Accounts, Admin) to manage customer records, maintain the product catalog, log inventory stock movements, and create sales delivery challans.

Key Features:

  • Customer CRM with search, filters (Lead/Active/Inactive, Retail/Wholesale/Distributor), and follow-up notes.
  • Product management with low-stock alerts and manual Stock IN/OUT adjustment logging.
  • Sales challans with item pricing snapshots and automatic stock deduction upon confirmation.
  • Role-based access control protecting routes and action buttons per user role.
  • Delivery challan print layout for generating customer invoices/delivery notes.

3. Database Schema

The system uses PostgreSQL managed via Prisma ORM. Below is the simplified structure of the data models:

User (id, name, email, passwordHash, role [ADMIN | SALES | WAREHOUSE | ACCOUNTS])

Customer (id, customerName, mobile, email, businessName, gstNumber, customerType, address, status, followUpDate, notes)

FollowUp (id, customerId, followUpDate, notes, createdBy, createdAt)

Product (id, name, sku, category, unitPrice, currentStock, minimumStock, warehouseLocation)

StockMovement (id, productId, quantity, movementType [IN | OUT], reason, createdBy, createdAt)

Challan (id, challanNumber, customerId, totalQuantity, status [DRAFT | CONFIRMED | CANCELLED], createdBy, createdAt)

ChallanItem (id, challanId, productId, productNameSnapshot, skuSnapshot, unitPriceSnapshot, quantity, totalPrice)

4. Business Logic & Workflows

Sales Challan Flow:

  1. Create Draft: Sales or Admin user creates a draft challan for a customer. A sequential challan number (`CH-0001`, `CH-0002`) is assigned.
  2. Add Items: Line items are added. The system records snapshot values of product name, SKU, and unit price so future product price edits do not alter old challans.
  3. Confirm Challan: When confirmed, a Prisma database transaction verifies available stock. If stock is sufficient, `currentStock` is reduced and a Stock OUT log is recorded. If stock is insufficient, an error is returned.
  4. Cancel Challan: If a confirmed challan is cancelled, stock is restored back to the product and a Stock IN log is recorded.

Inventory Stock Adjustment:

  • Warehouse staff can log Stock IN (restock) or Stock OUT (damage/return) entries.
  • Low-stock status triggers automatically when `currentStock <= minimumStock`.
